# V0.4 游戏设计摘要

## 核心闭环

```text
创建角色 / 选择职业
  → 天赋点确定 Build
  → 场景实体移动 + 热点探索
  → 条件机关 / D20 检定 / 环境状态
  → 意图制战斗 + 装备与战斗道具
  → 世界钟声推进
  → ACT I 烬冠承载者
  → 世界地图向东扩展
  → ACT II 雾外荒原
  → 收集虚空罗盘 / 荒原线索
  → 打开外封印黑门
  → 最终 Boss「门后之心」
  → 根据世界事实触发不同结局
```

V0.4 依然不依赖 AI。目标是让 Game Runtime 本身具有足够完整的玩法、持续世界状态和视听反馈；未来 DM Agent 只负责自由语言理解、叙事和受控内容编排。

## 双幕战役

### ACT I · 沉眠墓城

玩家调查维尔王朝墓城，逐步理解灰烬王冠其实是一道封印。第一幕 Boss「烬冠承载者 · 赫里昂」拥有三阶段，但击败他只会完成墓城篇章并打开王座后的东侧道路。

### ACT II · 雾外荒原

第二幕追加 12 个真实地图节点。玩家会接触灰风、镜砂、坠星、无旗骑士与另一套封印逻辑，最终找到「外封印黑门」。

关键推进采用可恢复设计：必要道具和最终黑门的检定失败不会永久消耗唯一机会。

## 意图制战斗与 Boss

战斗继续使用 V0.3 的敌人 Intent：

```text
attack / heavy / multi / defend / hex / drain / charge
```

V0.4 将同一规则用于第二幕敌人，并增加两名三阶段 Boss：

- 烬冠承载者：墓城封印的人格化残响。
- 门后之心：真正的 Campaign 最终 Boss；阶段变化拥有独立叙事和视觉演出。

前端动画只消费后端结果：伤害、阶段、状态、Intent、掉落都由 Go Runtime 决定。

## 场景实体与表现层

V0.4 增加 `sceneEntityLayer` 和 `vfxLayer`：

- 玩家角色在场景内有位置。
- 点击 SceneElement 时，角色先靠近交互位置。
- 战斗动作会触发斩击 / 爆发 / 防御 / 受击反馈。
- HP / 治疗 / 能量变化会生成飘字。
- Boss 入场、转阶段、区域切换、第二幕开启和最终胜利使用 Cinematic Overlay。
- WebAudio 动态合成短音效，无需打包额外音频文件。

表现层不写回规则，不是世界事实来源。

## Build 与装备

V0.3 的 12 个职业天赋与三槽装备完整保留。V0.4 新增荒原装备及战斗道具，让第二幕掉落继续参与已有 Build 系统，而不是开一套平行规则。

## 场景条件系统

`SceneElement` 继续表达：

```text
RequiresItem
RequiresFlag
HiddenUnlessFlag
ConsumesItem
Check
OnSuccess
OnFailure
```

V0.4 的关键例子：

```text
反向观测台
→ 调查罗盘匣
→ 感知检定
→ 获得虚空罗盘

外封印黑门
→ 必须持有虚空罗盘
→ 意志 DC15
→ 成功：解锁门后心室
→ 失败：触发风暴骑士战斗
→ 战斗后仍可再次检定
```

## 当前内容规模

- 3 职业
- 12 天赋
- 44 地点
- 41 个本地场景 SVG
- 130 个 SceneElement
- 35 个剧情 / 随机事件
- 21 类敌人
- 39 种物品
- 两幕主线 + 支线 / Lore / World Flag / 条件结局

## AI 接入后的角色

```text
玩家自然语言
→ DM Agent 解释意图
→ 结构化 Tool Call
→ Rule Engine 校验
→ World State 持久化
→ UI 根据真实结果播放表现
```

AI 不修改源码，也不能通过叙事文本绕开世界状态。
