# V0.3 游戏设计摘要

## 核心闭环

```text
创建角色 / 选择职业
  → 花费初始天赋点确定 Build
  → 点击场景热点探索
  → 条件机关 / D20 检定
  → 移动推进世界钟声
  → 观察敌人下一步 Intent
  → 攻击 / 技能 / 防御 / 战斗道具
  → 获得装备、线索与经验
  → 升级并继续选择天赋
  → 解锁隐藏区域
  → Boss 三阶段战斗
  → 根据世界事实触发不同结局
```

V0.3 仍不依赖 AI。目标是先让 Rule Engine、World State 和 UI 本身形成稳定游戏体验，未来 DM Agent 只增加自由语言行动、叙事和内容编排。

## 职业与 Build

每个职业 4 个天赋：

### 铁誓守卫

- 城墙誓言：强化防御行为。
- 处刑重势：职业技对重击 / 冲锋意图有额外压制。
- 墓守体魄：提升最大生命。
- 铁誓反击：格挡后形成反击能力。

### 暮影游侠

- 猎杀本能：19~20 暴击。
- 裂伤箭路：职业技施加流血。
- 暮影步：强化撤退 / 闪避。
- 遗迹拾荒者：感知调查和战利品概率提升。

### 余烬术士

- 余烬蔓延：职业技施加燃烧。
- 灰潮储能：提升最大能量。
- 残响汲取：技能命中后恢复生命。
- 符文护幕：进入战斗时获得一次保护。

## 意图制战斗

战斗不再是双方固定互殴。每回合开始前，前端展示敌人的下一步 Intent。

```text
敌人 Intent
├─ attack   普通攻击
├─ heavy    高伤害、低稳定性重击
├─ multi    多段攻击
├─ defend   本回合防御提高
├─ hex      施加负面状态
├─ drain    伤害 / 汲取类技能
└─ charge   冲锋攻击
```

玩家决策因此变为：

```text
看 Intent
  ↓
是否需要 Guard？
是否用职业技打断 / 反制？
是否用烟弹 / 霜盐等战斗道具？
是否趁防御前窗口抢伤害？
```

Boss 根据生命进入三阶段，阶段变化直接修改防御与玩家状态。

## 场景条件系统

`SceneElement` 除了原有 kind / action 外，V0.3 增加：

```text
RequiresItem
RequiresFlag
HiddenUnlessFlag
ConsumesItem
Check
OnSuccess
OnFailure
```

因此一个场景对象可以表达：

```text
先转动水闸
→ world flag: aqueduct_drained
→ 原本锁定的水下背包变得可调查
→ 玩家获得烟弹
```

或者：

```text
持有旧墓城图
→ 调查无钟之塔驱动机构
→ 感知 DC14
→ 成功：开启王室封藏间
→ 失败：没有解锁，可继续探索其他线索
```

## 世界钟声

`WorldClock` 是 V0.3 新增的持续世界状态：

```text
Bell      当前钟声 1~13
Steps     探索移动次数
Threat    威胁等级
LastChange 最近世界变化
```

每 5 次移动推进一次钟声。关键钟声会写入世界 Flag：

- 第 4 钟：第一次道路重排
- 第 7 钟：王庭残响开始寻找名字
- 第 10 钟：王座黑火苏醒
- 第 13 钟：整座墓城陷入异常寂静

Threat 会提升后续生成敌人的 HP / Defense。

## AI 接入后的角色

AI 不改代码，也不直接覆盖世界 JSON。它只通过被允许的 Tool 请求 Game Runtime 变更世界：

```text
自然语言行动
→ DM Agent 解释意图
→ Tool Call
→ Rule Engine 校验
→ World State 持久化
→ UI 渲染真实结果
```
